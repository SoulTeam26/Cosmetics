Same parser semantics as the in-game SoulPrint engine: first animation in the file, time-keyed vector / post / pre keyframes, easings, "loop": true repeats, "loop": "hold_on_last_frame" sticks the final pose until a movement key, otherwise one play and the vanilla pose returns. Position values are Bedrock model pixels (16 = 1 block), +Y in the file is UP (the client mirrors it into its Y-down model frame). Author-accident values (e.g. −4359 px = 272 blocks) are drawn as-is — that is the point: fix them in Blockbench, not here.

Props are pure JSON (props/<bone-name>.prop.json): an emote bone that is not one of the six player bones is a prop id, and this file defines every part and texture — geometry (box / sphere / cylinder) and textures (solid / checker / stripes / pixels) are generated in code, same as the client. Limits: 8 props per emote, 32 parts, ≤64×64 textures. Drop the file here or on the page; the Football sample shows one end-to-end.
